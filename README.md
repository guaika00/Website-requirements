# Project Tracker V5.1 · 协作中心与项目工具箱

本版本以 V4.1（含 admin / manager / operator / developer / viewer 角色）及 V5 协作中心为基础。

## 本轮包含

### 协作中心
- 项目工作台：按当前账号有权限的项目汇总需求总量、完成率、待验收、阻塞、加急与逾期。
- 任务讨论：评论、单层回复、从项目成员中 @ 提及。
- 站内通知：评论、提及、进度变化，以及登录/加载项目时检查并生成逾期提醒。
- 需求变更历史：自动保存需求字段更新前后快照。
- Tab 修复：详情抽屉在切换「进度记录 / 讨论 / 变更历史」时立即更新 active/aria-selected 样式；异步内容加载不再延迟选中态。

### 项目工具箱
- 甘特排期：使用计划开始日期、截止日期、负责人和状态展示任务时间线。
- 任务依赖：可设置前置任务；数据库阻止跨项目依赖及循环依赖。
- 需求模板：按项目保存模板并套用到新需求。
- 项目资料库：保存 Figma、文档、图片、网站、API 等链接。
- 工时记录：按项目/需求记录成员、日期、分钟数和说明，并汇总工时。
- 周报：生成最近 7 天摘要，可补充下周计划并下载 Markdown。
- 批次对比：比较各批次需求数、完成数和完成率。
- 项目复制：复制分类、批次和需求说明；新项目任务状态重置为待开始，不复制评论、成员、工时和私有图片。
- 外部只读分享：可创建带过期时间的分享链接、复制或撤销；公开页面只返回项目名称/说明和需求标题、批次、分类、优先级、状态、阻塞、截止日期，不暴露成员邮箱、评论和私有附件。
- 逾期提醒：客户端每 6 小时请求一次幂等数据库函数；通知只发给该项目运营成员和任务负责人。它不是邮件/Push 定时器，至少需要用户打开网站或加载项目才会触发检查。

## 升级前提
1. 已成功执行 V4、V4.1、普通管理员角色（如使用 manager）和 V5 协作中心迁移。
2. 现有 V5 的 `board_comments`、`board_notifications`、`board_requirement_versions`、`board_activity` 表存在。
3. 备份共享 Supabase 项目。此项目还承载 Travel app；本迁移仅新增/修改 `board_*` 看板对象及 `requirements.start_date / estimated_minutes` 两个看板字段，不修改旅行业务表、Auth 用户、XICHA 注册 Hook。

## 数据库升级
1. Supabase SQL Editor → New query。
2. 完整执行 `supabase/upgrade_v51_full_workspace.sql`。
3. 完整执行 `supabase/verify_v51.sql`，确认 5 张表、2 个需求排期字段、3 个 RPC 与 RLS policies 存在。
4. 如迁移失败，停止，不要先更新前端；保存第一条 SQL 错误供排查。

## 前端部署
1. 将升级补丁中的 `public/` 文件和 `vercel.json` 按原路径覆盖 GitHub 仓库。
2. 同时提交 `supabase/upgrade_v51_full_workspace.sql` 与 `supabase/verify_v51.sql`，方便留存迁移记录。
3. Commit 到 main，等待 Vercel 部署完成。
4. 强制刷新浏览器，测试详情 Tab、甘特图、模板、资料、工时、周报、批次对比、项目复制和分享链接。

## 权限与边界
- 所有项目数据表均使用 RLS，并通过 `board_can_view / board_can_edit / board_can_progress` 及项目成员权限控制。
- 只读成员可查看已授权项目数据和报表，但不能新增/修改项目工具数据。
- 工时可由本人和项目管理角色维护；项目管理角色可管理项目资料、模板、依赖和分享链接。
- 分享链接使用随机 token、可撤销、可过期；公开 RPC 只返回精简只读快照。
- 周报目前是按当前可见项目数据即时生成的 Markdown 下载，不是后台自动邮件发送。
- 工时目前为手动填报，不包含后台自动计时器。
- 甘特图当前为项目内日期条形排期视图，不是多月缩放的专业排程引擎。
- 项目复制不会复制私有图片、评论、工时或项目成员；避免意外泄露/复制历史协作数据。
